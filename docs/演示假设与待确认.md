# 演示假设与待确认

区分三类内容：**已确认业务**、**演示假设（用于实现，不视为正式业务确认）**、**范围外事项**。

## 一、已确认业务边界（来自执行包）

1. 校级实验室平台，按实验室隔离数据；后勤为另一套系统，不出现后勤菜单。
2. 管理端与普通用户使用端分开，本轮只做管理端；使用端申请用种子订单模拟。
3. 平台基础为菜单、角色、用户三项；菜单在角色中分配，不在中心重复配置。
4. 不建设中心档案管理页面；内置两个稳定实验室标识。
5. 同一用户可管理多个实验室，切换后按当前实验室的角色生效，权限不跨实验室叠加。
6. 全校视图仅用于查询；新增或处理业务须先选定实验室。
7. 外部个人、单位及附属医院不登录系统；管理员登记客户、代录业务，客户与操作人分别保存。
8. 内部动物属于库存，管理员出库后订单完成并扣库存；完整出库前不得标为完成。
9. 外购动物不入中心库存；进度停在「已发送供应商」，不登记到货或领取完成。
10. 外购少供、死亡等由管理员代登记反馈，关联原订单跟进，不自动退款、补供或调整费用。
11. 订购和饲养相互独立，订购完成不自动入场。
12. 动物订购默认系统内确认；平台可配置其他审核方式。
13. 自定义审批设计器、电子签名、检疫、繁育、设备预约、传感器、移动端、正式报表、伦理审查不做。

## 三、范围外事项（本轮不实现）

使用端、复杂审批引擎、科研全生命周期、预算系统、中心钱包、财务清算、供应商门户、后勤、真实通知、生产部署、充值余额自动扣减、退款、电子发票、回款核销、供应商付款。

## 四、待学校确认的问题清单

1. 扣费时点与扣费接口的真实字段、流水格式。
2. 饲养计费区间的正式口径（当前为演示约定）。
3. 外购异常的正式处理流程与是否允许调整费用。
4. 同一用户同一实验室是否允许多管理角色。
5. 外部客户结算方式（当前标记「外部结算待确认」）。
6. 库存类别是否需要做成可维护的类别管理页面（当前为校级预置档案，新增类别即改配置；实验室能否自建类别待确认）。
