权限说明：

- 菜单授权保存在角色数据中（`menuIds` + `actionKeys`），导航、直接路由访问、按钮操作三处一致校验。
- 操作权限标识：`service:edit`、`order:create/approve/reject/outstock`、`stock:in/loss/check`、`supplier:edit`、`purchase:batch/send/anomaly`、`feeding:entry/change/exit/supply`、`cage:edit`、`fee:generate/submit`、`system:edit`。
- 超级管理员为系统保护角色：不允许删除或停用。
- 全校视图（仅超级管理员）为只读汇总：所有写操作统一拦截并提示先选定实验室。
- 实验室切换只列出该用户有授权的实验室；无授权实验室时菜单为空且直接访问被拦截。

## 二、数据范围

- 所有业务实体携带 `labId`；列表取数统一经 `scoped()` 过滤，写操作再校验实体归属，防止跨实验室处理。
- 两个实验室放置了相似名称的数据（如「KM小鼠（SPF级）」），用于验证稳定 ID 与隔离。
- 分析测试中心的动物业务为**模拟隔离配置**，仅用于验证数据范围，演示时须说明。
- 库存类别为**校级预置档案**（实验动物、饲料垫料、试剂耗材、维修配件、其他物资），全校实验室共用；类别配置决定业务口径（`isAnimal`：订购出库只选动物类、饲养领用只选非动物类）与损耗原因选项（`lossReasons`）。新增类别只需加一条配置，不改业务代码。
