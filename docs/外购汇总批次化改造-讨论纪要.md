# 外购汇总「批次化」改造讨论纪要

日期：2026-11-12
范围：管理端「采购管理 → 外购汇总」功能
状态：方案已确认，本次同步实施代码改造

---

## 一、结论（已确认）

| 事项 | 结论 |
| --- | --- |
| 批次粒度 | 一个批次可跨多个供应商 |
| 未处理交互 | 按供应商分面板、面板内勾选订单、顶部聚合「生成发送批次」 |
| 生成批次动作 | 生成即发送（标记已处理 = 订单完成，无草稿中间态） |
| 已处理展示 | 按「批次」汇总（发送时间 / 操作人 / 涉及供应商 / 订单数 / 金额） |
| 导出文件 | 一个供应商一个 Excel（CSV），绝不混在一个文件里 |
| 一键导出多供应商 | 打包成 zip |
| 自动导出 | 手动为主：标记已处理后弹结果页附「按供应商导出 / 打包 zip」按钮 |
| 费用结转时点 | **待定，明天跟学校讨论**（本次保持现状「发送即结转」） |

## 二、明天跟学校讨论点（待确认）

> 外购订单费用，应在「发送供应商」时结转，还是「到货 / 交付后」再结转？
> 现状 Demo 为「发送即结转」（标记已处理时订单费用同步置为已扣费）。若学校要求到货后结转，需把「发送」与「费用结转」解耦。

## 三、现状代码位置（可溯源）

- 页面：`src/pages/purchase.ts`（外购汇总，三个页签：未处理 / 已处理 / 外购动物订单）
- 业务：`src/core/biz/purchase.ts`
  - `markOrdersSent()`：按订单直接标记已发送（现用）
  - `createBatch()` / `markSent()`：旧的「单供应商 + 草稿→发送」两步批次（页面已弃用，半成品）
- 类型：`src/types.ts` → `PurchaseBatch`（第 289 行，当前 `supplierId: string` 单供应商）
- 种子：`src/core/seed.ts`（第 1911–1921 行，`purchaseBatches` 种子）
- 导出：`src/core/utils.ts` → `downloadCSV()`（第 70 行，单个 CSV）
- 订单页单笔发送：`src/pages/order.ts`（`send_supplier` 操作，调用 `markOrdersSent([id])`）

## 四、本次改造要点

1. `PurchaseBatch` 由单供应商改为 `supplierIds: string[]`（跨供应商），状态简化为「生成即已发送」。
2. `markOrdersSent` 改为「生成跨供应商批次 + 标记订单已发送」，单笔发送也记为一个批次。
3. 移除旧的 `createBatch` / `markSent` 两步批次逻辑。
4. 未处理页：分面板 + 勾选 + 顶部聚合生成批次。
5. 已处理页：按批次汇总展示。
6. 导出：单个供应商 CSV + 多供应商打包 zip（无第三方依赖，store 模式）。
